# FortiGate policy naming

Policy names are generated by the Go backend. Values sent in `policy_name`,
`policy_comment`, `short_id`, or `naming_version` are not authoritative and are
recomputed before a draft is accepted, a diff is created, and a revision is
published.

Naming is enabled by defining `target_contexts`. Legacy documents without target
contexts remain readable during migration. Once a target context exists, every
object and rule must contain the structured naming metadata.

```json
{
  "tenants": [{"mkz":"M120","name":"Example","active":true}],
  "target_contexts": [{"name":"prod-vdom","context_type":"dedicated","assigned_mkz":"M120"}],
  "naming_catalog": {
    "version":"fortigate-v1",
    "zone_ranks":{"EXT":0,"OeDMZ":1,"GDMZ":2,"IDMZ":3},
    "zone_short_codes":{"OeDMZ":"OD","GDMZ":"GD","IDMZ":"ID"},
    "service_codes":{"tcp 443":"h","tcp 1433":"sql"}
  }
}
```

Networks and FQDN objects require a `zone`. Hosts may override the containing
network's zone. Rules use `rule_group`, `owner`, `change_reference`,
`review_date`, optional temporary-rule fields, `purpose`, `tenant_mkz`, and
`target_context`.

`POST /backend6/admin/policy-name-preview` accepts the complete editable policy
and returns the same generated names and comments that publication will use.
